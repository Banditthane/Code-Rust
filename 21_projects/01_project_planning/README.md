# Lesson 01: Project Planning

## Overview

การพัฒนาโปรแกรมที่ดีควรเริ่มต้นจากการวางแผนก่อนลงมือเขียนโค้ด

บทเรียนนี้จะฝึกวิเคราะห์โจทย์ กำหนดขอบเขตของโปรแกรม ออกแบบข้อมูล และแบ่งหน้าที่ของแต่ละส่วนก่อนเริ่มพัฒนา

## Learning Objectives

- วิเคราะห์ความต้องการของโปรแกรมได้
- กำหนดขอบเขตของโปรเจกต์ได้
- ระบุ Input และ Output ได้
- ออกแบบ Struct และ Enum เบื้องต้นได้
- แบ่งโปรแกรมออกเป็น Function และ Module ได้
- วางแผนการทดสอบโปรแกรมได้

## 1. Understand the Requirements

ก่อนเริ่มเขียนโปรแกรม ให้ตอบคำถามต่อไปนี้:

- โปรแกรมนี้สร้างขึ้นเพื่อแก้ปัญหาอะไร?
- ใครเป็นผู้ใช้งาน?
- ผู้ใช้ต้องป้อนข้อมูลอะไร?
- โปรแกรมต้องประมวลผลอะไร?
- โปรแกรมต้องแสดงผลลัพธ์อย่างไร?
- มีกรณีผิดพลาดอะไรที่ต้องรองรับ?

## 2. Define Input and Output

ตัวอย่างโปรแกรมเครื่องคิดเลข:

**Input**

- ตัวเลขตัวที่ 1
- ตัวดำเนินการ
- ตัวเลขตัวที่ 2

**Processing**

- ตรวจสอบตัวดำเนินการ
- คำนวณผลลัพธ์
- ตรวจสอบการหารด้วยศูนย์

**Output**

- ผลลัพธ์การคำนวณ
- ข้อความแจ้งเตือนเมื่อข้อมูลไม่ถูกต้อง

## 3. Design Data Structures

เลือกชนิดข้อมูลให้เหมาะสมกับงาน เช่น

- Struct สำหรับเก็บข้อมูลที่มีหลาย Field
- Enum สำหรับข้อมูลที่มีสถานะหรือประเภทชัดเจน
- Vec สำหรับเก็บรายการข้อมูล
- HashMap สำหรับข้อมูลแบบ Key-Value

## 4. Design Functions

แบ่งการทำงานออกเป็น Function ตามหน้าที่ เช่น

- รับข้อมูลจากผู้ใช้
- ตรวจสอบข้อมูล
- ประมวลผล
- บันทึกข้อมูล
- แสดงผลลัพธ์

แต่ละ Function ควรมีหน้าที่ชัดเจนและไม่รับผิดชอบงานมากเกินไป

## 5. Organize Modules

เมื่อโปรแกรมเริ่มมีหลายส่วน ควรแบ่ง Module ตามความรับผิดชอบ เช่น

```text
src/
├── main.rs
├── models.rs
├── services.rs
└── utils.rs
```

โครงสร้างนี้เป็นตัวอย่างเบื้องต้น สามารถปรับตามขนาดและความซับซ้อนของโปรเจกต์ได้

## 6. Plan Testing

กำหนดกรณีทดสอบอย่างน้อย 3 ประเภท:

1. Normal Case: ข้อมูลถูกต้องและทำงานตามปกติ
2. Edge Case: ข้อมูลอยู่บริเวณขอบเขต เช่น จำนวนเป็นศูนย์
3. Invalid Case: ข้อมูลไม่ถูกต้อง เช่น ป้อนข้อความแทนตัวเลข

## Best Practices

- เริ่มจากฟังก์ชันหลักที่จำเป็นก่อน
- อย่าเพิ่มความสามารถที่ยังไม่จำเป็น
- ตั้งชื่อ Function และ Variable ให้สื่อความหมาย
- แยกส่วนรับข้อมูลออกจากส่วนประมวลผลเมื่อเหมาะสม
- วางแผน Error Handling ตั้งแต่เริ่มต้น
- ทดสอบแต่ละส่วนก่อนรวมเข้าด้วยกัน
